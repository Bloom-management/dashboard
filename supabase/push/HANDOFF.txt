Delivery behavior
- SQL transaction ID groups the jobs created by a single calendar import into
  one city/user summary. First eligible publication per job is unique forever.
- New jobs recheck approved city, opt-in, slots, current assignments, review hold,
  active property/city, cancellation and cleaning end time immediately before send.
- Reminders use public.cities.notification_timezone. Detroit is America/Detroit.
  Other cities must be assigned a valid IANA timezone before reminders are enabled.
  Property-local checkout dates are retained. No browser timezone or fixed offset.
- Evening slot: 18:00, tomorrow. Morning: 08:00, today. Only assignments claimed
  by that slot are eligible. Read current assignments at delivery. Withdrawing,
  cancelling or completing removes eligibility. No immediate claim push.
- Late claims after evening appear next morning; claims after 08:00 do not cause
  a retroactive morning summary. Reminders expire after 10 minutes; no hours-late
  catch-up. New alerts expire after one hour. Provider TTL is capped at 60 seconds.
- Durable device outbox: pending -> attempted -> accepted/failed/skipped; leased
  FOR UPDATE SKIP LOCKED reservations, unique logical keys, stable OneSignal
  idempotency UUIDs, four attempts maximum and bounded exponential retries.
  Each tick reserves five devices concurrently; monitor backlog/expired entries
  before scaling beyond the initial small cleaner group.
- Provider acceptance is NOT proof of device delivery or viewing. No fabricated
  read receipts. Invalid/expired subscription responses disable the binding.
- No personal schedule content is sent in the provider payload. The worker asks
  Bloom for current safe counts using the verified device capability and checks
  the bound Clerk session on the server. If offline, signed out, switched, expired
  or no longer eligible, it shows a generic 'Open Bloom' message, never stale
  private counts. A visible fallback is necessary for Safari's push policy.
- Sign-out/account-switch invalidates via both global lifecycle reconciliation
  and live Clerk session validation. Re-verify on subsequent login/session.
  Multiple devices can be independently verified. A device whose browser storage
  was cleared may need its old OneSignal subscription removed before re-registering
  if the provider restores the same subscription ID (fail-closed conflict).
- Clicking opens a sanitized local Cleaner view/date. Sign-in retains that URL;
  normal server role/city/assignment checks still apply. The URL grants no access.
